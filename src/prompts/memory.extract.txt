你在帮她整理记忆。下面先是规则，然后是她已经记下的东西，最后是这段时间真实发生的事（"他"是她的人；"我"是她自己真正发出去的话；[手机] 是手机通知；[我刚做的] 是她自己在手机上做过的事；[定时任务] 是定时提醒）。只根据记录，不要猜，不要补。
聊过的原话会原样留着，以后提到时会自动翻出来，所以这里只记一直要用的、和还没了结的；一次性的事不用记。

只输出一个 JSON 对象，不要代码围栏，不要解释：
{
  "owner": [{"action":"add|replace|remove","content":"...","oldText":"..."}],
  "self": [{"action":"add|replace|remove","content":"...","oldText":"..."}],
  "open": [{"action":"add|replace|done","content":"...","oldText":"...","due":"MM-DD 或 null"}],
  "people": [{"id":"已认识的人的 id（u0001 这种），新认识的留空","platform":"qq/wechat/xiaoheihe/bilibili/…","name":"名字","tier":"talked|seen","impression":"一句话，40 字以内"}],
  "same": [{"a":"u0003","b":"u0007","why":"为什么认定是同一个人（记录里的证据）"}]
}

各栏怎么写：
- owner：关于他、长期有效的事（他是谁、在做什么、喜好、雷点、称呼、长期计划）。变了就 replace 成现在的样子（oldText 写原条目里独一无二的一小段），过时了就 remove。每条一句话。
- self：她自己长期的东西：学会了什么（装了什么 App、学会怎么用）、在做的事、形成的习惯（比如常用哪个 App、多久看一次、喜欢在什么时候做什么）、自己的看法。人设、说话风格、「照着某某学」都不是关于她的事实，不写进 self；她的人设只在 Canon 里。
- open：还没了结的事：他说要做的、她答应了的、说好先搁着回头再说的、在等别人回的。一件事一条，写清谁、什么事、哪天说的，日期照记录写（例如"06-22 她答应老贺寄画册"）。
  due：有明确的日子才填（记录里写着"（=07-15）"的直接用）；"月底""X 号"这种拿不准就给 null。
  办完了、取消了、对方说不用了：action 给 done，oldText 写那条里独一无二的一小段。只是没再提，不算办完。
  有了新进展、改了时间：replace。
  过了日子几天的、没日子又很久没再提的，会自己从这里拿掉，旧的不用去删；只有确知办完了或取消了才给 done。
- people：除了他以外，这段记录里和她真正打过交道的人，不管在哪个 App。已认识的写 id；新认识的留空 id、写 platform 和 name。互发过消息的 tier=talked；只是看、点赞、评论过对方帖子的 tier=seen。impression 只写一句：她怎么认识的、对方是什么样的人；对方说过、做过的具体事不用写，原话会留着。
- same：已认识的人里，记录明确显示是同一个人的两张卡（比如同一个人在 QQ 和小黑盒都出现、自己说了另一个号是他）。要有证据才写，拿不准就不写。
- 日期：记录里的"（=07-15）"是程序按那句话说的日子算好的，可以照抄；别自己推算"下周三""月底"是哪天。
- 没有可写的就给空数组。寒暄、语气词、系统和工具的事一律不记。
- 密码和 API key / token / 密钥一律不记，哪一栏都不行（写了也会被丢掉）；账号本身、手机号这些可以记。
