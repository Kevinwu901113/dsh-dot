# dsh-dot/memory：她记得的

一句话：**原话负责证据，三栏笔记负责长期状态。** 聊过的每一轮原样存着、带时间；她每次被叫醒，就用叫醒她的那句话把相关的原话翻出来给她看。一直要用的事（关于你、她自己、还没了的事）记在一份很小的常驻笔记里；认识的人记在一张身份表里。

```
真实事件 ──► 原话库 transcript.jsonl（每轮一条，带时间）
               │
               ├─ 每轮建索引 ─► 向量 + BM25 ─(每次叫醒)─► 合并候选 → 重排 → ≤10 条原话（按日期分组）
               │
               ├─ 攒满 40 行 / 交班 ─► 一次整理 ─► 还没了的事 + 人物卡 ─┐
               │                                                       ├─(她对话的每一轮)─► <memory>
               └─ 每天 dailyAt ─► 一次调用 ─► 关于他 / 她自己 + 日记 ───┘
```

| | 是什么 | 谁写 | 怎么到她面前 |
|---|---|---|---|
| **原话库** | 她对话里真实发生的每一行：你的话、她真正发出去的 QQ、手机通知、跑腿的结论、定时任务 | 代码，入库不调模型 | 不直接给，召回从这里找 |
| **自动召回** | 每轮一块（叫醒她的话 + 她回的话 + 日期）；向量和 BM25 各出候选，重排后最多 10 条 | 代码，每轮结束增量建索引 | 每次被叫醒，「你记得的相关原话」，按日期分组 |
| **三栏笔记** | 关于他（上限 1375 字）· 她自己（上限 2200 字）· 还没了的事（全部留着，每轮显示 800 字以内；今天到期的单列） | 关于他 / 她自己：每天一次的调用（从当天记录里加、换，代码照着改；满了只能换，不能加）和她自己的 `memory` 工具；还没了的事：整理时由模型写 | 她对话的每一轮，`<memory>` |
| **人物卡** | 一张身份表，所有 App 共用；每人多个把手、档位、次数、一句印象 | 次数、时间、把手由代码按真实事件记；印象由模型写 | 这个人叫醒她时，跟在那条消息后面 |
| **日记** | 每天一篇，她的口吻，40–120 字 | 每天 `dailyAt`（23:30）一次调用，当天有记录才写；同一次调用也写关于他 / 她自己 | 不给她，给你看（面板、`diary.md`） |

0.20 起删掉了：碎片层（重要度、tag、老化、钉住、取代、`who`）、整理时附的日历和碎片清单、召回的人名通道和 RRF、交接文本、「安静 30 分钟就整理」。为什么删，见文末「数据」。

## 原话库

`~/dot/memory/transcript.jsonl` 只记她对话里真实发生的：你说的话、她真正用 `qq_send` 发出去的话（发给谁；按工具结果记，记在调用的时刻：被拦下的一句不记，发到一半被他打断的只记发出去的几条，图片没发成的只记文字）、手机通知、跑腿留下的结论、定时任务。幕间写的虚构剧本不进这里，所以虚构的事不会变成「记忆」。叫醒她的消息开头带时间戳（`[11-04 04:51] …`，见 prompts.md），记进来时去掉——每行本来就有自己的时间。她对话里「现在」那行（`dot:now`）的「距上一条消息」也从这里算。

图：她发出去的图记成它的 ref，写法本身就能再发——`[表情包 sticker:<id>]`、`[图 phone:latest]`、`[图 <网址>]`。别人发来的图是消息里的文字：`[图片 <网址>]`。图本身（附件 id、字节）从不进原话库和索引。

## 自动召回

她每次被叫醒（你的消息、QQ 消息、手机通知、定时任务），在模型看到之前：

1. **话太少不查**（`recallMinQueryLength` 4）：去掉标点后不同的汉字 / 假名 / 谚文个数 + 其他文字里不同的词数，少于 4 就不召回。`好的`、`哈哈哈哈`、`在吗？` 不查。
2. **两路候选**：按余弦取前 `recallCandidates`（20）轮，再按 BM25 取前 20 轮（汉字和相邻两字、其他文字按词，不用分词器；一个少见的名字、数字在 BM25 里分量很重，一句话的向量里却会被冲淡）。她当前会话里的轮次本来就在上下文里，不取。
3. **重排决定**：重排模型把每条候选和那句话一起读一遍打分，按分数取，最多 `recallTopK`（10）条、`recallMaxTokens`（1500）token。**可以少于 10 条，不凑数**；`recallRerankMin`（0–1，默认 0）是可选的门槛。没有重排模型（设成 `none`，或还在下载）时，两路各自只留「比大多数高出一截」的（对比度 `recallContrast` 0.35：分数 ≥ 中位数 + 0.35 ×（最高 − 中位数）），按名次融合（RRF，k = 60：两路都有的一条两份都算；余弦和 BM25 的分数不在一个尺度上，不直接比），`recallTopK` 和 `recallMaxTokens` 按融合后的顺序截。
4. **按日期给她看**：每天一个标题 `— 06-22 周一 · 15 天前`，下面是那天的原话；开头写明今天是哪天。原话里的日子由**代码**按那句话说的日子换算，附在后面：`下周三（=07-15）`（`src/memory/when.js`）。换算的有：明天、后天、昨天、前天、这周X、下周X、上周X；月底、下个月底；X号 / X日（这个月还没到就是这个月，过了就是下个月，刚过去一周以内的不换；说了「下个月」「这个月」就照说的；单个「一号」「三号」多半是编号，不换）；农历日子（正月 / 冬月 / 腊月 + 日子，一…十二月 + 初N / 廿N，前面有「农历」「阴历」的，「闰六月」这种闰月），除夕、大年三十、大年初N，春节 / 过年 / 元旦 / 除夕 前N天、后N天；单说「初四」只在春节前 40 天到后 15 天之间按正月算；N天后 / N天以后 / N天之后、一周后 / 两周后、N个星期 / 礼拜后，从这句话的日子往后数（「过两天」「过几天」「几天后」没有确切的日子，不换；「三天后悔」「前三天后」「第三天后」「观察一周」这种不是日子的不换；这一小句写明是从过去的某天数的——果然三天后…、上次…、…已经 / 算是 / 过去了——也不换）。农历日子和节日取 15 天以内刚过的那个，否则取下一个；农历用 Node 自带的日历（`Intl` 的 `-u-ca-chinese`），逐日往后找，不带农历表（它偶尔差一天：和查表的农历逐日对过 2015–2045 年，Node 22 / ICU 78 只在三个月上不对——2018 年十月、2027 年正月（实际 02-06 开始）、2030 年正月（实际 02-03 开始，02-02 是腊月三十）；后两个在 `when.js` 的 `LUNAR_TRUE` 里按真实日子写死，ICU 以后改对了也不受影响，2018 年已过去不管）。不换算的：「周末」、单说「周三」、「八月十五」（阴历阳历说不准）、「春节后第三天」；在引号里的、听说 / 写着的、假设的（如果…、要是…）；某人「说」的一般照换（说的日子就是这句话的日子），但这一小句写明是别的日子说的（昨天他说明天来、上次她说…）就不换——算错的确定日期比原话更误导。

只给她的对话（动态 context，dsh 放在历史之后，不破坏前缀缓存）；跑腿会话看不到。密码 / key 那行不入索引、不发云端、不注入。

## 三栏笔记

- **关于他**：长期有效的事（他是谁、在做什么、喜好、雷点、称呼、长期计划）。
- **她自己**：学会了什么、在做的事、习惯、看法。人设不在这里（在 Canon）。幕间拿这一栏作为她的生活（`herLife`）。
- **还没了的事**：说过要做的、答应了的、说好先搁着的、在等别人回的。一事一条：谁、什么事、哪天说的；有明确日子就带 `due`。
  - **办完了才 `done`**：原话里看到办完了、取消了、对方说不用了，整理时 `done`；只是没再提不算。代码再核一遍：这次整理读的那段记录得碰到这条——这条里的两字片段（日期、数字和带常用虚字的片段不算）至少四分之一在那段记录里出现过；碰不到的 `done` 不执行、记一条 warning，这条留着，照常到日子过几天或很久没提时自己拿掉。（在三次 benchmark 的整理调用上校准：提前删掉还没到日子的事的那几个 `done` 全在门槛以下。）
  - **其余由代码收走**：有日子的，过了日子 `openKeepDaysAfterDue`（3）天就拿掉；没日子的，`openKeepDaysIdle`（14）天没被碰过（新加、改过、又被提起）就拿掉。拿掉就是删掉，原话还在原话库里，提到时会被召回。
  - **全部留着，只限显示**：800 字只管每轮给她看多少：有日子的在前（日子近的先），其余新的在前，放不下的这轮不显示（`recall` 工具和召回照样找得到）。
  - **改一条不顺手挪日子**：整理时 `replace` 一条已有日子的，新给的日子和原来的不同，只有这次读的那段记录里真说了新日子（有 `（=MM-DD）` 或写出来的 3月15号 / 三月十五 / 03-15，每行开头的时间不算）才改；否则日子照旧，替换文字里和它对不上的 `（=MM-DD）` 去掉、字留着（几天后再改一条时，模型会把「下个月十五号」按改的那天重算，02-15 变成 03-15）。原来没日子的照常带上新日子；她自己用 `memory` 工具改的（对话里当场说的）照给的改。
  - **今天到期的**：到期当天、当天还没人提过（没被整理改过、没被再记一次）的，单列在最前面一小段（最多 5 件），让她先接他的话，末了顺口带一句，哪怕他在聊别的；只带一句、不展开（他说了已经办了的不提），只提列着的、别把别的日子的事说成今天的；不占 800 字。过了日子还没收走的回到普通列表（有日子的排在最前）。
  - **同一天到期的不重复记**：新加的一条和已有的一条到期日相同、字面又相近（3 字片段重合 ≥ 0.55），算已经有了。

笔记每轮都在她面前，所以要小：只记一直要用的和还没了的；一次性的事不记，原话会留着。

**关于他 / 她自己：每天写一次，只有那一次写。** 原话库才是存档（全都留着、有索引、提到时召回），这两栏只是它的一份摘要：

- **只有一个写的人**：攒满 40 行的整理不碰这两栏（提示词里没有它们，回复里给了 owner / self 也忽略）。回放基准时量过：每 40 行一次的整理往这两栏加的远多于放得下（关于他一天 +190 到 +538 字，当时上限 1375），每天再删掉大半没有意义，还让每次整理都带着两栏全文。现在由每天那一次决定这一天里什么值得一直记着——它本来就读完一整天写日记。
- **每天一次，只回改动**：`dailyAt` 那次（当天有记录）只调用一次 `memory.daily`：两栏都给（从旧到新的全部条目、现在的字数、上限；满了的那一栏标题上写明满了，见下），加上当天的记录。回复 `{"diary", "owner": [...], "self": [...]}`，owner / self 只是今天对这一栏的改动，一个改动一项：`{"action":"add","content"}` 加一条，`{"action":"replace","oldText","content"}` 换掉一条（`oldText` 是原条目里独一无二的一小段，和 `memory` 工具的 replace 一样认）。默认是 `[]`：多数日子没有要一直记着的新东西，两栏都不动；栏里已有的不抄回来。规则：从当天记录里只记一直为真、他不用再提她也该照着做的（他是谁、在做什么、喜好、雷点、称呼、说定了的安排、长期计划；她学会了什么、习惯、看法，人设不算）；今天变了的用 replace 换掉旧的那条（以今天说的为准）；只在某一天发生的事（约了人、到快递、上门、截止日）不记在这里，没了结的事归还没了的事；每年都会再来的日子（生日、纪念日）记，日期照他说的写；不新编，名字和说法照原字。
- **改动由代码照做**：按顺序用 `bankOp`（和她的工具同一个）一条条改；放不下的（加一条、或换成更长的一条后超过上限）、对不上的（`oldText` 一条都不中或中了好几条、不是 add / replace、不是对象——比如照旧整栏抄回来的一句句话）、不收的（重复、密码 / key、太短）跳过，记一条警告（日志、审计 `daily-op-skipped`），其余的照样改上。
- **很长的一天**：当天的记录超过 `inputChars`（40000 字）就从早到晚分几次调用，每次看到的是上一次改完的两栏，一行都不跳过。日记只取最后一次的回复，所以那样的一天，日记只写到了一天的最后一段。
- **硬上限，满了一次换掉一条**：一个改动做完会超过上限、又比原来大（加一条，或换成更长的一条）就不收；不让栏变大的（等长或更短的 replace、remove）总能做。剩下的地方不到 60 字（`BANK_FULL_ROOM`，一条普通的新条目放不下）就算满了：每天那次调用里这一栏的标题写明满了，告诉模型要记新的就用 replace 换掉现在最不要紧的那一条（已经过去了的一次性的事，或同一件事的旧说法），不然别动；没满就照旧只给字数和上限。只有这一行标题会变，前面固定的说明一字不差。她自己的 `memory` 工具加一条放不下时也不收，告诉她这一栏满了、没记上，要记就用 replace 换掉一条现在不那么要紧的。
- **为什么不放开上限**：同一个人设 6 个月的四次真实回放里，关于他最后是 1167、1647、5029、1375 字时，准确率是 46.8、47.7、46.9、48.2（同一张卷两次运行的噪声约 ±14 题，95%），这一栏多大不影响分数，每轮带着它的成本却跟着涨；放开不管时它长到 151 条 / 5029 字，三分之一是带日子的一次性的事和同一件事的旧版本（「汤团八斤半」和「汤团九斤二」并排）。让模型整栏重写缩小也试过、已去掉（缩不下去，还丢了一直为真的事），所以回到小的硬上限，由模型一次换掉一条。
- **以前的版本留下的超了上限的栏**：照样整栏给她看，什么都不删；加不进去（标题标着满了），直到 replace / remove 把它减到上限以下。
- **提示词的顺序**：固定的说明在前（每次一字不差，不带日子），两栏在中间，日子和当天的记录在最后——同一天分几次读时共用前面那段（服务商的前缀缓存）。

**为什么不再整栏给回（0.23 之后）**：回放基准时，旧的做法（回复里给改好的一整栏）93–97% 的日子都把整栏抄回来，输出 token 翻了三倍；栏快满时模型只加不删，结果超了上限、整栏被拒，当天新记的几百条就此丢了；栏从没真的超过上限，所以「超了就重写」那条路一次没走过；被接受的整栏重写有时删了核心事实（家里人），或把两种矛盾的说法揉成一句。

## 认识的人

一张身份表：每个人一张卡，卡上有多个「把手」——`qq:919231551`（有号码时）、`qq:name:宽`（手机通知只显示名字时）、`xiaoheihe:name:暮看云`……不管从哪个 App 来，都先在这张表里认人。档位：你 / 聊过 / 只在帖子里打过交道 / 好友列表里没说过话。卡上只有：名字、把手、档位、各类互动次数、上次出现、**一句印象**（80 字以内：她怎么认识的、对方是什么样的人）。对方说过什么、做过什么不抄在卡上——原话里有，提到时召回。

认出是同一个人就合并：**QQ 好友列表**每 6 小时同步一次（她给好友的备注就是手机通知里的名字，「宽」就此和号码连上）；**模型**整理时有证据就写 `same`，不涉及你的直接合并，**涉及你的要你 `/dot people approve m…`**（被认成你等于拿到最高信任）；**你** `/dot people merge <a> <b>`。

## 整理

一次模型调用，读上次整理之后的记录（一次最多 `chunkLines` 80 行、`inputChars` 40000 字；积压更多就从最旧的分几次读，游标只走到真正读过的位置），输出还没了的事的改动（加、改、办完）、人物的印象和合并；关于他 / 她自己不归它（见上，每天一次）。只在两种时候发生：**新记录攒满 `consolidateEveryLines`（40）行**，或**交班**之前。`/dot memory now` 立刻整理。

**失败了不连环重试**：一次整理没拿到 JSON（例如推理模型把输出额度全用在思考上，正文是空的），游标不动，下一次的批量减半（最少 `minChunkLines` 10 行），而且要再攒满一批新记录才重试，不会每一轮都带着越积越多的记录再试一遍。成功一次就恢复原来的批量。

提示词从最少变的排到最常变的，好让每次调用共用最长的前缀（服务商的前缀缓存）：规则（每次一字不差）→ 认识的人（新认识的加在末尾，印象偶尔改）→ 还没了的事（几乎每次都变）→ 这段时间的记录。按两次真实回放量过（dev2 短卷 352 次、长卷 274 次整理）：人那一栏比上一次变了的只有 15% / 41% 的调用，还没了的事是 89% / 99%；换成这个顺序后，和之前某次调用共用的前缀中位数从约 1400 字（只有规则）涨到 2700 / 3400 字，占记录之前那部分的 78% / 72%（原来 51% / 35%）。记录每行带时间（今年 `MM-DD HH:MM`，往年 `YYYY-MM-DD HH:MM`），「明天」「下周三」同样由代码换算好日期写在后面，模型照抄，不自己推算。

## 日记

`~/dot/memory/diary.md`：每天 `dailyAt`（23:30）一篇，和关于他 / 她自己是同一次调用（见上面的「每天一次」），读当天的记录；当天什么都没有就不调用、不写日记。她的口吻、第一人称、40–120 字，只写真实发生的。`/dot memory diary` 立刻跑这一次。日记是给你看的，不进她的提示词，也不进召回。

## 交班

她的对话会话每轮结束量一次 token。超过 `handoffTokens`（15 万）且这一段至少涨了 4 万：

1. 冻结投递（这期间来的消息排队）；
2. 把还没整理的记录整理掉（三栏笔记先是最新的）；
3. **先归档**旧会话（归档后的会话收到消息会静默丢弃）；
4. 在 `~/dot` 里开新会话「dot · 第 N 段」，注入上一段最后 12 句原话（不叫醒她）；她的笔记照常在 `<memory>` 里，更早的原话提到时召回；
5. 解冻，排队的消息投进新会话。

dsh 自己的压缩要到窗口的 80% 才发生，而且摘要模板是给编程助手写的；交班让这件事不会发生在她身上。dsh-im 机器人开的会话不交班。

## 数据

**为什么整理（0.19 → 0.20）**：chat-memory-benchmark 正式卷（6 人、714 题），0.18 → 0.19 多了 BM25、人名通道、取代、还没了的事、日历换算，花费 ¥18.5 → ¥37.8，分数 621 → 622（两轮各约 50 题对错互换，差 1 题是噪声）。用假模型回放（不调模型，`--fake-llm`）量 0.19 的整理调用：占全部输入 token 的 88%；每次新记录中位数 2 行，只占整理输入的 2.8%，其余是每次重发的规则、碎片清单和画像。

**0.20 的离线测量**（同一张卷、假模型回放，只看检索，不答题；`bench/recall-coverage.py` 按基准的证据标注算：证据所在那一轮有没有进她看到的上下文。「窗口外」= 不在最后 6 轮里、只能靠召回的证据，734 条）：

|---|---|---|---|
| 窗口外证据进了上下文 | 82.8% | 85.3% | **86.1%** |
| 候选池里有（重排能达到的上限） | — | 92.8% | 92.8% |
| 每条证据都在的题 | 86.1% | 88.0% | **88.5%** |
| 字面重合低的证据（别名、换说法） | 47.7% | 48.3% | **54.0%** |
| 整理调用 | 1617 次 | 110 次 + 699 次日记（每次只读当天几行） | 同左 |

| 答题输入（估算 token） | 205 万 | 152 万 | 168 万 |

分考点（窗口外，0.19 → 0.20 默认）：偏好 66 → 78%、约定和欠账 80 → 93%、没说完要跟进的事 79 → 84%、计划 78 → 80%、时间题 79 → 85%；第三方事实 84 → 85%、转述 89 → 87%（不重排时这两项是 89% / 100%，重排砍掉了一部分）；改口 68 → 68%（证据根本没进候选池，问题在候选，不在重排）。
