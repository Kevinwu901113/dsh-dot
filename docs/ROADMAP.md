# dsh-dot 总体规划（2026-10-23；2026-11-25 按 0.25.2 重写了「现在在哪」和架构；2026-11-26 按 dev 补了 0.25.2 之后的改动）

## 一句话

dot 是一个**在自己手机上过日子的角色**：有自己的手机、账号、作息；你是她 QQ 里的一个联系人；两次对话之间她在过自己的生活。能干活是附带的，不是主体。

## 现在在哪（dev，0.25.2 之后，2026-11-26）

0.25 把「一个模型同时拿主意、动手、说话」拆成三处，各只读它该读的；事实只记在代码写的账上。细节见 `DESIGN.md` 的「0.25：三处模型、两本账、一个出口」和其后的几段补记；0.25.2 之后的改动见 `DESIGN.md` 文末 11-26 的几段。

| 层 | 状态 |
|---|---|
| 拿主意（她的对话） | 人设卡 + 记忆 + 事情簿。只有插件为她开的那一个对话是她，在她的工作区里手动开的会话不是。不碰设备，不带宿主的工具（`dot` 预设）；事情交给手，话交给「说」 |
| 动手（`dot/hands`） | 一件事一个会话，没有人设、记忆、QQ。四个地方各有自己的预设和工具：手机、她的电脑、查资料、他这台电脑本机。一个地方一把锁：各自一次一件，不同地方同时做；交到正忙的地方当场告诉她在做什么，不排队；别的会话（qq-bridge 管理员私聊）直接用手机、电脑时也占这把锁。做完用 `done` 收尾，要人定的用 `ask_her` |
| 说（`dot/say`） | 一次干净的调用：只有人设的「说」部分、最近的原话、事情簿给的事实。所有说出去的话走一个出口（`dot/outlet`） |
| 事情簿（`dot/ledger`） | 交给手的每件事一条，只存事实字段，只由代码写。在做、做完、卡住、谁叫停、在等谁回，都以它为准 |
| 手艺簿（`dot/howto`） | 按地方记每件事走了几步、成没成、花多少；值得学的地方由一次小调用写笔记，她睡着时核对一遍。去留待定（见下） |
| 要他的事（`dot/gates` + `dot/consent`） | 四档：不做 / 他本人来 / 先问他 / 她自己的。没有按钮，她用自己的话问；他开口要的事算同意，但对外联系别人的一步只认他话里说到的那个人 |
| 记忆 | 原话库 + 召回；事实条；还没了的事；关于他 / 她自己每天整理一次；人物卡；她知道的说法 |
| 什么叫醒她 | 他的话、有人发来的通知、定时任务、自己的时间、手做完一件事。都从一个入口进她的对话；时间上的事挂在一个 30 秒的时钟上。没有定时看手机。自己的时间：他上一句话或她的一天开始之后安静 `idleMinutes`（30）来一次，用过就记下；她可以自己留一个「下次」 |
| 出错 | 模型调用怎么结束分成几种：额度用完、登录或 key 失效以插件名义告诉他一次，后台的请求先不发；「说」那次空着回来不当成她不说话，再问一次；被截断直接认出；上下文超长立即交接 |
| 作息 | 醒着 → 快睡着 → 睡着，是一个状态；睡着后只有他叫得醒；夜里的整理和核对挂在「睡着了」上 |
| 设备 | 手机（Android 模拟器）、电脑（microVM，可选）、电脑上的 QQ、本机（只读自由，改动先问他） |

```
   他的话 ─┐                                   ┌─ 手机
   通知 ───┤                                   ├─ 她的电脑
   定时 ───┼─▶ 拿主意（人设 + 记忆 + 事情簿）─ hands ─▶ 动手 ─┼─ 查资料
 自己的时间 ┤        │            ▲                    └─ 本机
 手做完了 ─┘        │            └──── 事情簿（代码记）◀──┘
                    └─▶ 说（只有人设和事实）─▶ 出口 ─▶ QQ
```

**还没定的**（2026-11-25）：
- 手艺簿加夜间核对留不留：先补跨天记忆和长流程任务的有/无对照，再定。
- 她怎么学：方向是记录和验收由代码固定，学习只走原话召回加她自己记的笔记，她提的改动过了回放才留。正式设计文档还没写（`LEARNING.md` 是作废的旧草案）。
- 接话那一行没有检查；换对话期间结果要等近一分钟。

## 现在在哪（0.24.x，2026-11-19，旧）

> 下面这张表是 0.24 时的样子，留作记录：「定时看手机」11-20 删了；「她说一步，手做一步」11-20 起改成一整件事交给手做完；「每天两段自己的时间」11-26 起改成「安静一阵来一次」。

0.24 把「两次对话之间的生活由一个模型来写」（幕间的叙述者）整个拿掉了：它写的东西和真发生的事分不开，会被当成事实带进对话。现在的原则是**她的日子只由真做过的事组成**。

| 层 | 状态 |
|---|---|
| 她（对话） | 只有一个她。人设卡 `persona.md` 固定；说出去的话过代码检查（括号动作去掉，检查表上的说法退回改一次） |
| 手（`dot/hands`） | 手机和电脑由另一个会话操作：没有人设、记忆、QQ。她说一步，手做一步，结果和画面回到对话。没有跑腿、`hand_off`、`tell_him` |
| 记忆 | 原话库 + 召回；事实条；还没了的事（有日子的到期提醒）；关于他 / 她自己由每天一次的整理写；人物卡；她知道的说法 |
| 什么叫醒她 | 他的 QQ、手机通知、定时看手机（默认 30 分钟）、定时任务、每天两段自己的时间、手做完一步 |
| 主动找他 | 没有次数上限和意愿值，只给事实（今天找过几次、回了几次、哪条没回） |
| 设备 | 手机（Android 模拟器）、电脑（microVM）、电脑上的 QQ，和 0.22 时一样 |

**还没有的**：幕间拿掉以后，「过日子」只剩自己的时间和通知，没有东西让她的日子有连续性（惦记的事、在追的东西、下一步想做什么）。这是下一步要设计的，约束是只认真做过的事。

```
        他的 QQ ─┐                          ┌─ phone ──── Android 模拟器
      手机通知 ──┤                          │
  定时 / 自己的时间 ─┼─▶ 她的对话（人设卡 + 记忆）─ hands ─▶ 手的会话 ─┼─ computer ─ microVM
      手做完一步 ─┘        │                └─ （结果和画面回到对话）
                           └─▶ 说的话 ─ 检查 ─▶ QQ
```

以下各节是 2026-11-12 之前的规划，留作记录；其中幕间（剧本、打算、去看、玩、试、成长）相关的条目已经不成立。

## 架构（0.22 时的，旧）

```
                 ┌─ phone ──── Android 模拟器 ── mcp__dot-phone__* ── 通知事件
dot (联系人层) ──┼─ computer ─ microVM（可选）── mcp__dot-vm__*
                 └─ interlude ─ 幕间：剧本/连续性/打算/去看/主动联系
          ▲ 叫醒（通知、定时、幕间观察）        ▼ 投递（dsh-im send / 未来 qq_send）
        她的会话（dsh 自己跑对话，人设 = Canon 段 + 工作规则段）
```

原则：**她只能看，不能瞒着你动**（幕间只读；有后果的动作走审批或不给）；**不替她做她该自己做的事**（装 App、登录后的日常）；**不重复造轮子**（模拟器、mobile-mcp、HDSI 预设、dsh-im、dsh 定时）；**可审计**。

## 分期

### P0 · 把"聊天"这条线做扎实（本周）

目标：你在 QQ 里和她聊一天，不漏、不串、不重复。

1. ~~**忙时攒消息**~~：已做（`held`/`releaseHeld`，`groupNotifications`），10-29 真机验证。
2. ~~夜间静音~~：11-20 并进「她的作息」（`dot.awakeHours`，默认 08:00–23:00）：睡着时别人的通知留到她醒来，不丢；他找她照常。
3. **回消息的速度**：先接受 ~1 min（人也不秒回）；记录每次回复的耗时和工具调用数，一周后看数据再决定要不要快路。
4. **观察一周**：`calls.jsonl`、`web-context.jsonl`、两份审计日志。不加功能。已看到的：10-27/28 余额不足时幕间一天失败 133 次——现在失败后退避 5/10/20…60 分钟。

完成标准：连发 5 条她一次回齐；夜里不叫；一周内 0 条漏回（审计可查）。

### P1 · 让她"过日子"真的发生（下周）

目标：幕间不再只是躺床上；她会拿手机、会去看、会有话题。

1. ~~**定时拿起手机**~~（11-20 去掉：有新通知才给她看，没有不叫她，见 DESIGN「没有看手机这个动作了」）。
2. ~~**`phoneApps` 填上**~~：内置常见 App 表，按她手机上装了什么生效（11-02）；`vmSites` 给电脑。
3. **她关注什么**：由你给（账号/话题），原样写进 Canon 的 `world`；或者等她在对话里自己长出来。我不编。
4. **intent 空转**：`intent` 轮只结算不新建（现在每天 7 轮 intent 滚自己）。
5. **幕间观察结果回流**：`webContext` 已进下一轮；检查剧本里有没有真的用上。

完成标准：一周内剧本里出现 ≥3 次"她在手机上看到的东西"；幕间 intent 轮 ≤ 2/天。→ 11-02 核对 ~/dot/interlude：phone-check 186 次；观察 phone 6 / web 4；剧本里小黑盒评论、番茄、手机存储都是真事；intents 已清空。达标。

### P2 · "玩"：轻动作（已做，待真机观察）

目标：点赞、评论、发帖、关注——在她的账号上，按她的人设，低频。

1. 提示词来源：社区（NapCat 陪伴机器人们的 proactive 提示、HDSI 社区的 agency 讨论），不自己写。
2. 机制：幕间产出 `playIntent`（想做什么、为什么、意愿值）→ dot 以**正常轮次**执行（不是只读观察）→ HDSI 的 agency 门控（活跃时段、意愿阈值、每日上限）。
3. 审批策略：点赞/评论/关注在白名单内不审批；发帖、私信陌生人、付款审批；账号资料改动不给。
4. 风险接受：小号，封了就封了。

完成标准：一周 ≤ N 次动作（N 你定），审计里每次都有"为什么"。

### P3 · 通道与第二设备（按需，不排期）

- ~~**NapCat 当她的"电脑端 QQ"**~~：已做（`dsh-dot/qq`，v0.6 起；v0.10 加 SnowLuma 后端），见 [qq.md](qq.md)。
- **dsh-im 官方机器人通道**：降级为可选（给想用的人），她的 IM 身份以真 QQ 为准。
- **真机 / PVE 24 小时**：`serial` 配置项接真安卓机（去模拟器检测、Mac 睡眠也在线）；或手机搬到 PVE 的 Redroid。等有需要。
- **NotificationListenerService APK**：只在 dumpsys 快照被证明会漏时做。

## 风险

- **平台检测 / 封号**：模拟器 + 自动化违反各家条款。小号、低频、不绕验证码。
- **模型成本**：（旧：每次叫醒一轮 + 幕间一天 ≤12 轮 + 定时看手机 ≤30 轮/天；这两样都已删。）现在的上界由代码数：一件事 `thingCostCap`、自己的时间每段 / 每天的 token 上限（手在她自己的事上的花费算在里面）；面板上看每天的用量。
- **许可证**：幕间提示词已重写（不含 HDSI 文字），整包 MIT；0.3–0.22 的版本仍是 AGPL。
- **单点**：Mac 睡眠 = 她下线。P3 的真机/PVE 解决。
