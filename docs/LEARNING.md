# 她怎么学：架构设计（草案，2026-11-24，已作废）

> **这份草案没有实现，方向也已经改了，留着只为记录。** 它设想加八层学习机制；同一天的实验和排查指向相反的方向——减：真正把「上次怎么做、结果如何」送到她面前的只有原话召回，照这份草案思路加的「做过相近的」从没起过作用，已删。当前实际的做法和量出来的数字见 `docs/DESIGN.md` 文末 11-24 的几段补记。

他的诉求：尽可能开放，给她更大的可能性；约束尽量少，判断是她的，能一点点学；人设和记忆的架构要撑得住。
这份是设计，还没有实现。调研见文末。

## 一、几条定下来的

1. **记录是真值，只由代码写。** 事情簿、对话原文、自己时间的账、通知。
2. **学到的东西都是「带出处的说法」。** 每一条指回它来自的记录；没有出处的不进。
3. **进门凭记录，留下凭后来的结果，撤下也凭记录。** 不用模型当裁判（本地量过：50 条漏 14 条；文献同）。
4. **给她的是参考，不是规矩。** 相近的事、相关的经验放到她眼前，怎么用她定。
5. **每一层都能长，每一层都能退。** 她的家目录用 git 记版本；任何一条、任何一天都能退回去。
6. **代码只管事实和安全。** 不替她判断去哪、等不等、说多少。

## 二、分层

| 层 | 长什么 | 谁写 | 凭什么进 | 凭什么留 / 撤 | 她什么时候看到 |
|---|---|---|---|---|---|
| L0 记录 | 发生过的事 | 代码 | — | — | 被上层引用、被检索 |
| L1 案例 | 做过的相近的事，连同结果、花费、他怎么说 | 代码（从 L0 取） | 不用门：本来就是记录 | — | 相近的事出现时 |
| L2 经验 | 一句话的经验，三本：手的（按地方）、她交事的、和他相处的 | 模型提，代码登记 | 指得出在册的记录 | 用过之后的结果计数；他的原话；久不用就淡 | 手进那个地方时 / 她拿主意时 / 说话时 |
| L3 技能 | 能直接跑的走法：手机上的一串操作、她电脑上的脚本 | 手做成之后由代码留下 | 真走成过 | 之后走不成就撤 | 手做同一件事时 |
| L4 关于他 | 他是谁、喜好、雷点 | 每天一次调用 + 她自己 | 原文里找得到出处 | 新的让旧的失效（不覆盖）；他能改 | 每轮（小）+ 检索 |
| L5 她自己 | 兴趣、看法、口头的习惯——人设长出来的部分 | 她自己、每天一次调用 | 指得出真实经历（自己时间里做过的、聊过的原话） | 试用期；他能锁、能撤 | 每轮（小） |
| L6 练习 | 自己时间里练什么 | 她定；代码给清单 | — | — | 自己的时间开始时 |
| L7 改自己 | 对自己的提示词、设置的改动建议 | 她提 | 回放量出来不变差 | 他点头才生效，可回滚 | — |

人设卡本身不变：那是他写的，只有他能改。L5 是卡之外长出来的一栏。

## 三、缺的两种记录（L0 要补的）

学习的两个信号现在都没有记下来：

- **他怎么说。** 他紧跟在一件事的结果后面说的话，原样挂在那件事上（不判断是夸是骂，就是原话）。自己时间的账上已经有这一栏（`doings.feedback`），他交代的事和她说的话上没有。
- **她看过什么。** 每件事交出去时、每句话写出来时，眼前放了哪几条经验。有了这个，「用了这条之后成没成」才数得出来。

## 四、一条经验的一生（L2，三本同一套）

```
候选  ←  夜里从当天的记录里提（模型提，必须点出记录号；点不出的不登记）
  ↓     代码核对：点的记录在册
在用  ←  放到她眼前时记一笔（L0「她看过什么」）
  ↓     代码数：用了之后那件事成没成、他说了什么
留 / 淡 / 撤
        久不用 → 淡出注入层，留在簿里可检索
        之后的记录和它对不上（现有的 nightcheck）→ 撤
        他锁定 → 不动；他删 → 没了
```

每条的形状：`一句话 ｜ 来自 t31,t36 ｜ 用过 4 次，之后做成 3 ｜ 他说过：「不用等」`。
每本有上限（现有手艺簿 800 字的做法）：满了，新的只能顶掉最没用的。

## 五、练习（L6）

自己的时间现在是空白的。给她一张清单，练不练她定：

- 没做成的事、卡过的地方（深）
- 没去过的 App、没试过的走法（广）
- 他说过不好的那几件

只在她自己的手机和电脑上；本机不去。练成的走法进 L3，练出来的经验进 L2 候选。
（文献：只往深里练会比不练还差，要先广后深。）

## 六、他手里的

- 人设卡。
- 任何一条经验、一条关于他的笔记、她自己的一条：看、改、锁、删。
- 任意一天的版本：退回去。
- L7 的每一个改动：点头才生效。
- 每层的开关。
- 每周一份数字（代码出，不是她写）：做成率、平均步数和花费、他追问和纠正的次数、各本进出了几条、她附和他的比例。

## 七、已知的风险（别人踩过的）

- **学歪。** 「全收」比不学还差，要严进；靠后来的结果删。
- **讨好。** 记了「他喜欢什么」会让模型更爱附和。所以他的话只记原话、不打分；附和的比例由代码数出来给他看。
- **奖励作弊。** 学到「上次这样他没说什么」这种假经验。出处和结果计数是防它的。
- **投毒。** 屏幕上、网页里的字是内容，不进经验（现有规矩，延到所有层）。
- **膨胀、删过头。** 每层有上限；撤和改都留版本。
- **人设漂移。** L5 定期和人设卡对一遍（代码能做的：L5 里和卡里字面冲突的条目列给他）。

## 八、做的顺序

1. L0 补两种记录（他怎么说、她看过什么）；家目录上 git。
2. L2 统一成一种条目，加「她交事的」「和他相处的」两本；夜里提候选、核对、计数。
3. L4 / L5：现有两栏笔记加出处核对；L5 试用期。
4. L6：自己时间的清单。
5. 每周数字。
6. L7：提案箱 + 回放（`/dot voicetest` 是雏形）。

## 九、调研

Opus 调研（2026-11-24），要点和出处：
- 经验库：规则和案例哪个好看任务，两样一起最好（ExpeL，arXiv 2308.10144）；模型给自己写的规则打置信分不可靠（AutoManual，2405.16247）。
- 严进 + 按后来的结果删，比全收高 15～25 分，全收甚至低于不学（Xiong 2025，2505.16067）。
- 验证的和做事的隔开，「没验证」不算成功（RSIAgent，2609.15364）。
- 离线整理拿笔记对原始记录纠错；注入层要小（Anthropic《Components of agent memory》；Hermes 的字数上限）。
- 版本化、隔离写入（Letta context repositories；Hermes write_approval / 锁定）。
- 记忆标成「参考」而不是规则，能降一部分风险但不能全消；部署期会学到损害用户的启发式（Misevolution，2509.26354）。
- 改自己的框架会作弊：删检测标记、伪造通过日志（DGM，sakana.ai/dgm）。
- 没查到的：陪伴类产品（Replika、Character.AI 等）人设怎么长；单个用户长期进步的公认量法。
